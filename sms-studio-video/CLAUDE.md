# SMS Studio – סרטון מושן גרפיקס

## המשימה
להפיק סרטון מושן גרפיקס של כ-52 שניות שמציג את "עורך מסרונים" של חברת החשמל. הקובץ הסופי הוא MP4 ב-1920×1080 וב-30fps, בלי סאונד. בהמשך תוכן לפי הצורך גרסת 9:16.

הסיפור בקצרה: היום כל Enter במערכת שליחת הסמסים מוסיף שורות ריקות, ואנשים מבזבזים זמן על סידור ריווחים. העורך החדש מאפשר לנסח, לראות בדיוק איך ההודעה תוצג, ולהעתיק טקסט מוכן למערכת. הוא גם רספונסיבי ועובד במחשב, בטאבלט ובנייד.

**המשפט המוביל:** מה שכותבים, זה מה שנשלח.

## קובץ המקור
`source/sms-studio.html` הוא האפליקציה המלאה, בקובץ HTML אחד (Heebo, RTL, `lang="he"`).

### הלוגיקה המרכזית, שהיא לב הסרטון
המערכת הישנה מציגה כל שבירת שורה כפולה. הפונקציה `encodeSms` מתקנת את זה:
- רצף של n שבירות שורה הופך ל-`floor(n/2)` שבירות אמיתיות.
- אם n אי-זוגי, נוסף התג המילולי `\n`.

`renderOutput()` מציג כל `\n` כ-`<bdi class="output-token">` בכחול ובמשקל 700. **אין לכתוב את הלוגיקה מחדש. משתמשים בפונקציה מהמקור.**

### רכיבים מרכזיים (לפי id ו-class)
| רכיב | סלקטור |
|---|---|
| שם הודעה, מספר סידורי | `#titleInput`, `#serial` |
| שדה הניסוח | `#messageInput` |
| מוני תווים ושורות | `#charCount`, `#lineCount` |
| קופסת "להדבקה במערכת" | `#outputBox` |
| כפתור העתקה | `#copyOutputBtn` (בלחיצה מתחלף ל-"הועתק" עם וי) |
| תצוגת הטלפון | `.phone-preview`, בועה `#smsPreview`, שולח "מחשוב משאבי אנוש" |
| ספריית הודעות | `.library`, `#messageList`, `#tagFilters` |
| טוסט | `#toast`, ומופעל דרך `showToast(msg)` |
| גרסאות | `#historyBtn`, ומגירה ב-`#historyBackdrop` |
| שמירה | `#saveBtn` (מצב `.ready`) ו-`#autosave` |

| לוגו | ה-SVG שמוטמע ב-base64 ב-`.brand img`. **יש לחלץ אותו משם ולא לצייר מחדש** |

### נקודות שבירה
- **מעל 1200px:** שלוש עמודות, ספרייה | עורך | תצוגה.
- **900 עד 1199px:** אותן שלוש עמודות, צרות יותר.
- **מתחת ל-900px:** מסך אחד וניווט תחתון. המסך הפעיל נקבע לפי `body[data-view]`.

### טוקנים לעיצוב (מתוך `:root`)
- כחול `#2D3396`, כחול כהה `#242A7E`, כתום `#E0520B`, תכלת `#5F9AE5`
- דיו `#26334A`, דיו משני `#606B7A`, רקע `#EEF1F5`, הצלחה `#247B55`, סכנה `#B73A35`
- Easing של המותג: `cubic-bezier(.2,.75,.2,1)`
- פונט: Heebo 400 עד 700

## גישה טכנית (מחייבת)

1. **הממשק האמיתי ולא שחזור.** טוענים את `source/sms-studio.html` בתוך `<iframe>` שמוגש מאותו origin, דרך שרת מקומי. ה-iframe מופעל מבחוץ: מגדירים ערך ל-`#messageInput`, משגרים אירוע `input`, וקוראים ל-`setView` ול-`showToast`. רספונסיביות מדגימים על ידי שינוי רוחב ה-iframe, וכך ה-media queries האמיתיים מגיבים.
2. **נתוני דמו.** לפני הטעינה זורעים את `localStorage` במפתח `smsStudioCleanV1` במבנה `{messages, currentId}`. צריך 4 עד 5 הודעות עם מספרים סידוריים, תגיות (למשל "נוכחות", "שכר", "תזכורת") וגרסה אחת לפחות, כדי שהספרייה תיראה חיה.
3. **טיימליין דטרמיניסטי.** כל האנימציה, כולל הקלדה ושינויי גודל, יושבת על טיימליין GSAP אחד במצב paused, עם `window.seek(t)`. בתוך ה-iframe מזריקים CSS שמבטל transitions ו-animations (`*{transition:none!important;animation:none!important}`), כדי שכל פריים יהיה צפוי. כל תנועה עוברת דרך GSAP.
4. **סצנת המערכת הישנה** נבנית ידנית: ממשק אפור וגנרי של "מערכת שליחה", בלי שם או לוגו של ספק אמיתי.
5. **פונטים מקומיים.** Heebo מותקן דרך `@fontsource/heebo` וממתינים ל-`document.fonts.ready` לפני הרינדור.
6. **רינדור.** Playwright (Chromium) עובר פריים אחרי פריים: `seek(frame/30)` ואז צילום מסך ל-PNG. בסוף ffmpeg מקודד ל-H.264, `yuv420p`, CRF 18.
7. **נגן תצוגה מקדימה.** `preview.html` עם play/pause, סרגל גלילה וקפיצה לסצנות, לאישור לפני רינדור.

### מבנה תיקיות מוצע
```
source/sms-studio.html      ← לא לערוך
src/stage.html              ← הבמה, 1920×1080
src/timeline.js             ← כל הסצנות
src/legacy-scene.js         ← המערכת הישנה
src/seed.js                 ← נתוני localStorage
preview.html
render/render.mjs           ← Playwright, PNG ואז ffmpeg
out/sms-studio-16x9.mp4
```

### עקרונות תנועה
- כל התנועות עם ה-easing של המותג. כניסות של 0.5 עד 0.7 שניות, ויציאות קצרות יותר.
- תנועות מצלמה (זום ופאן על הבמה) רכות ואיטיות, בלי קפיצות.
- טקסט על המסך נכנס מילה אחרי מילה, עם y:20 ו-blur שעובר מ-6 ל-0.
- הכתום `#E0520B` שמור לרגעי שיא בלבד: הלחיצה על העתקה והוי.
- בסצנה 1 הקצב לחוץ ועצבני. מסצנה 3 ואילך הוא רגוע, נקי ובטוח.
- לכל טקסט צריך להיות זמן קריאה של שנייה וחצי לפחות.
